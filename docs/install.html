Install & Setup

Get AgentGraph running in minutes — from install to a fully indexed knowledge graph accessible to your AI agents.

Prerequisites

You need Python 3.12 or later and uv (the fast Python package manager).

# Install uv if you don't have it
curl -LsSf https://astral.sh/uv/install.sh | sh
Install
1

Clone and sync dependencies

git clone https://github.com/simonexmachina/agent-graph
cd agent-graph
uv sync --extra all

The --extra all flag installs all connector packages (Slack, Discord, Google, Gmail). You can install only what you need — see the connector guide.

Authenticate

Run the interactive setup wizard to connect your data sources. It steps through each installed connector and opens the relevant auth flow.

agentgraph onboard

Or authenticate with a specific platform:

agentgraph auth google     # Google OAuth2 (Docs, Sheets, Drive, Gmail)
agentgraph auth slack      # Slack cookie credentials
agentgraph auth discord    # Discord bot token
Credentials are stored locally. All tokens and cookies are written to the AgentGraph config directory on your machine (~/.agentgraph/ by default, or AGENTGRAPH_CONFIG_DIR if set). Nothing is sent to any external server.
Run the server

The server handles connector polling, incoming fetch-URL requests from the browser extension, and serves the web viewer at http://localhost:8899.

agentgraph serve

To auto-reload on code changes during development:

agentgraph serve --reload

Server logs are written to /tmp/agentgraph.log.

Browser extension

The extension passively indexes content as you browse — triggering a fetch whenever you dwell on a supported page (Slack, Discord, Google Docs/Sheets/Drive, Gmail).

1

Build

cd extension
npm install && npm run build
2

Load in Chrome

Go to chrome://extensions → enable Developer mode → click Load unpacked → select the extension/dist/ directory.

3

Verify

Open a Slack channel or Google Doc in Chrome. After a few seconds the extension icon should show activity, and the entity should appear in the knowledge graph.

agentgraph search "slack" --limit 5
Connect to Claude or ChatGPT

The MCP server exposes the full knowledge graph to Claude Desktop, Claude Code, ChatGPT developer mode, and any other MCP-compatible AI assistant. Run this to get the config snippet:

agentgraph mcp-config

Then paste the output into your MCP client's config file. See the command reference for transport options (stdio, SSE, streamable-http).

Run in the background

To keep AgentGraph running automatically without a terminal window, register it as a system service.

# 1. Find the full path to your agentgraph binary
which agentgraph
# → e.g. /Users/you/.local/bin/agentgraph

# 2. Create the plist (replace the Exec path as needed)
cat > ~/Library/LaunchAgents/com.agentgraph.serve.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.agentgraph.serve</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/you/.local/bin/agentgraph</string>
    <string>serve</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardOutPath</key>
  <string>/tmp/agentgraph.log</string>
  <key>StandardErrorPath</key>
  <string>/tmp/agentgraph.log</string>
</dict>
</plist>
EOF

# 3. Load it now (also starts automatically on login)
launchctl load ~/Library/LaunchAgents/com.agentgraph.serve.plist

# Check it's running
launchctl list | grep agentgraph

# Stop / restart
launchctl unload ~/Library/LaunchAgents/com.agentgraph.serve.plist
launchctl load   ~/Library/LaunchAgents/com.agentgraph.serve.plist
# 1. Find the full path to your agentgraph binary
which agentgraph
# → e.g. /home/you/.local/bin/agentgraph

# 2. Create a user-level systemd unit
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/agentgraph.service <<'EOF'
[Unit]
Description=AgentGraph local knowledge graph server
After=network.target

[Service]
ExecStart=/home/you/.local/bin/agentgraph serve
Restart=on-failure
RestartSec=5
StandardOutput=append:/tmp/agentgraph.log
StandardError=append:/tmp/agentgraph.log

[Install]
WantedBy=default.target
EOF

# 3. Enable and start
systemctl --user daemon-reload
systemctl --user enable --now agentgraph

# Check status / logs
systemctl --user status agentgraph
journalctl --user -u agentgraph -f
# Start in background, persist across terminal close
nohup agentgraph serve >> /tmp/agentgraph.log 2>&1 &
echo "PID: $!"

# Stop it later
pkill -f "agentgraph serve"
Note on the MCP server. The agentgraph mcp-serve command (stdio transport) does not need to run as a background service — the MCP client launches it on demand. Only agentgraph serve (the HTTP backend + connector poller) benefits from the above setup.
