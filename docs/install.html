Install & setup

Set up AgentGraph once, authenticate the data sources you care about, then keep the graph running as a local service that your browser and AI clients can use.

Prerequisites

AgentGraph expects Python 3.12 or later and uv.

curl -LsSf https://astral.sh/uv/install.sh | sh

Install

  1. Clone the repository and sync dependencies

    --extra all installs every first-party connector package.

    git clone https://github.com/simonexmachina/agent-graph
cd agent-graph
uv sync --extra all

Authenticate

The fastest path is the setup wizard. It walks every installed connector and opens the required auth flow.

agentgraph onboard

You can also authenticate one connector at a time.

agentgraph auth google
agentgraph auth slack
agentgraph auth discord
Local credential storage: credentials live in ~/.agentgraph/ by default, or under AGENTGRAPH_CONFIG_DIR if you set a custom config directory.

Run the server

The server accepts browser dwell events, runs connector pollers, serves the graph viewer, and provides the local HTTP backend.

agentgraph serve

Use reload mode during development.

agentgraph serve --reload

Logs are written to /tmp/agentgraph.log.

Browser extension

The extension is the browser-side observation layer. It watches supported URLs and asks the server to fetch the underlying resource after the dwell threshold is met.

  1. Build the extension

    cd extension
npm install
npm run build

  2. Load it in Chrome

    Open chrome://extensions, enable Developer Mode, then load extension/dist/ as an unpacked extension.

  3. Verify capture

    Open a supported page such as a Slack channel or Google Doc and confirm entities start appearing in the graph.

    agentgraph search "slack" --limit 5

Connect Claude or ChatGPT

Use the generated MCP config for stdio clients, or run a remote transport for clients that expect SSE or streaming HTTP.

agentgraph mcp-config
ChatGPT: enable Developer mode in Settings, then add a remote MCP connector that points at an AgentGraph SSE or streaming HTTP endpoint.

The command reference has the exact MCP transport options.

See MCP reference

Run in the background

Only agentgraph serve needs to be long-running. MCP stdio mode is spawned on demand by the client.

macOS launchd

which agentgraph

cat > ~/Library/LaunchAgents/com.agentgraph.serve.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.agentgraph.serve</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/you/.local/bin/agentgraph</string>
    <string>serve</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardOutPath</key>
  <string>/tmp/agentgraph.log</string>
  <key>StandardErrorPath</key>
  <string>/tmp/agentgraph.log</string>
</dict>
</plist>
EOF

launchctl load ~/Library/LaunchAgents/com.agentgraph.serve.plist

Linux systemd

which agentgraph

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/agentgraph.service <<'EOF'
[Unit]
Description=AgentGraph local knowledge graph server
After=network.target

[Service]
ExecStart=/home/you/.local/bin/agentgraph serve
Restart=on-failure
RestartSec=5
StandardOutput=append:/tmp/agentgraph.log
StandardError=append:/tmp/agentgraph.log

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now agentgraph
